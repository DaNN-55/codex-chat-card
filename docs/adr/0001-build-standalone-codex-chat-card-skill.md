# ADR-0001：构建独立的 Codex 对话卡片 Skill

## 状态

已接受

## 日期

2026-09-22

## 决策驱动因素

- 让用户在 Codex 中完成整个流程，不额外引入桌面应用。
- 直接读取当前 Codex Desktop 会话日志。
- 导出前允许用户选择对话轮次。
- 生成平台无关的长图，并可作为后续加工素材。
- 跟随用户当前的 Codex 外观，同时不耦合某个 Codex 应用版本。
- 将未来的会话来源适配与轮次选择、渲染行为隔离。

## 备选方案

1. 构建独立桌面应用。
2. 构建带确定性本地渲染器的独立 Skill。

## 决策结果

**采用方案**：包含配套脚本的独立 `codex-chat-card` Skill。

Skill 负责对话工作流。Codex 适配器把会话日志规范化为已完成轮次；轮次选择与内容视图相互独立，因此同一组选中轮次可以显示双方、只显示用户或只显示 Codex。Markdown 布局和主题只处理最终可见内容。默认输出是一张高度自适应的长图；固定尺寸切片只能作为可选衍生物，而不是标准文档模型。

默认主题从用户本机 Codex 配置解析。渲染器读取外观、强调色、颜色、字体和字号，并对表格、链接、列表、代码和聊天气泡应用维护中的 Codex 风格 Markdown 组件规则。链接跟随本机强调色，因此默认 Codex 配置会得到熟悉的蓝色链接。实现不会解析或依赖已安装应用的打包源码。本机样式解析失败时回退到 `codex-ink`，用户仍可显式选择任一内置固定主题。

### 正面影响

- 用户可以在 Codex 中通过自然语言显式调用工作流。
- 可以新增会话来源适配器而无需重写渲染器。
- 长图母版不包含对特定发布平台的假设。
- 本机明暗外观变化会在下次导出时自动反映。
- 用户显式选择固定主题时，输出保持稳定且可复现。

### 负面影响

- Skill 包含一套小型 Node.js 运行时及其依赖。
- 当前 Codex 日志格式需要明确的兼容性夹具。
- Desktop 外观配置键不属于公开的 Codex 配置契约，未来可能变化，因此本机解析必须保持宽容并保留经过测试的回退路径。
- 超长图片仍受渲染器和查看器资源限制。

## 验证

- 无需中间 JSON 转换即可解析真实的当前 Codex Desktop 会话。
- 使用稳定编号和预览列出可选轮次。
- 导出最近轮次、连续范围和离散轮次。
- 在 PNG 中渲染 GFM 表格、链接、代码块、中文和 emoji。
- 使用每个内置主题渲染同一选择。
- 解析具有代表性的本机明暗配置并验证回退行为。
- 使用自动本机主题导出真实对话，并目视检查表格、链接、列表标记、字体和气泡。
